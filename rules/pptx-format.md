# pptx の体裁

部品は `doc_tools/deck_lib.py`。作ったら必ず `doc_tools/render_pptx.py` で PNG にして全ページを見る。

## 1. 色で内容の意味づけをしない
色はオブジェクトの種類だけを表す（見出しの帯＝紺 `012169`、表の見出し行・ラベル＝グレー `75787B`、本文＝`222222`、注記＝`666666`）。判定・区分・役割・強調の数値を色で塗り分けない。
**Why:** 色に意味を持たせると凡例が要り、内容の区別は文字で読めば足りる。
**How to apply:** 色が要りそうなときは、まず太字で出してユーザーに確かめる。見た目の良さを求められた資料だけ、テンプレートのテーマ色を基調にする。

## 2. 本文は14pt を基本にする
見出しは16pt前後。収まらないときは文字を小さくせず、折り返し・箱の高さ・レイアウトで吸収する。12pt は凡例・補足だけ。1文字だけの折り返しは改行位置か文言で避ける。フッター・ページ番号（9pt）はテンプレートのまま。
**Why:** 収めるために文字を小さくしていき、「全体にフォントが小さい」と指摘された。

## 3. テンプレートがあれば体裁を完全に踏襲する
会社・顧客のテンプレートを docs/ に置き、`Deck(..., template=..., layout=...)` で使う。レイアウトの名前・本文域の座標・小見出しの枠（placeholder の idx）を最初に調べて、`deck_lib.py` の X0・W と `slide(sub_idx=)` を合わせる。小見出しの枠には文字だけを入れ、色・大きさを上書きしない。表はスタイル ID を外して明示の書式だけにする（deck_lib の table がそうしている）。

## 4. リード文（スライドのタイトル）は2行まで使ってよい
1行に収めるために情報を削らず、根拠の数値・条件・結論を1文（体言止め）に入れる。20pt で1行あたり約44字なので、約86字までが目安。

## 5. ページ数より密度
薄いページは統合し、左右2カラム・上下2ブロックで詰める。詰め込みすぎて14pt に収まらないなら文言を削る。

## 6. 角丸の箱に直角の見出し帯を重ねない
見出し帯が角からはみ出る。見出し付きの箱は、箱も見出しも直角で作る。

## 7. スペルチェックの赤波線を出さない
python-pptx は文字の連なり（run）に言語を書かないため、PowerPoint が英語として日本語を判定し赤波線が出る。全 run の `a:rPr` に `lang`（日本語を含むなら `ja-JP`、英字だけなら `en-US`）・`altLang`（その逆）・`dirty="0"` を付け、`noProof="1"` は英字・記号だけの run に限る（deck_lib の style_run がそうしている）。
**Why:** ユーザーの望みは「校正を止める」ことではなく「作ったものに波線を出さない」こと。日本語に noProof を付けると、後でユーザーが直したときの校正も止まる。

## 8. PNG で確かめる
はみ出し・重なり・シェブロン内の折り返しは、XML を調べても分からない。全ページを PNG にして見る。Copilot ならチャットに PNG を添付して確かめさせてもよい。

## 9. ページごとに図の形を変え、1ページに1つ注目点を作る
全ページを「薄い色の箱を並べる」同じ型にしない。伝えたい関係に合う形を選ぶ（集約・層・柱・流れ・ロードマップ・階段・左右対称・循環など）。各ページに1つだけ、目が行く場所を作る（濃い色の塗り・大きな文字・吹き出し・強調の輪）。アイコンは円の中に置いて、ページをまたいで同じ描き方にする。
**Why:** 体裁は合っていても、全ページ同じように箱が並んでいて「どこに注目すべきか、ぱっと視覚的に理解できない」「デザイン性に乏しい」と指摘された。
**How to apply:** 構成を決めるときに、ページごとに「形」と「注目点」を1行で書き出してから作る。PNG を並べて見て、同じ見た目のページが続いていないかを確かめる。手本は `doc_tools/examples/guide_deck.py`。
