# 資料の構成

## 1. 項目立ては全要素で揃えて埋める
一部の要素にだけ補足がぶら下がる構成にしない。例：フローの全ステップに「実施者／前提／通過条件／NG時の対応」を定義する。
**Why:** 項目が揃っていると抜けがなくなり、要素どうしを比べられる。埋まらない欄が出るなら、その欄の定義が甘い。

## 2. 対象の特性が違えば、構成そのものを変える
複数の対象（工程・ゲート・領域）を「同じ型に中身を差し替えただけ」で作らない。
**How to apply:** 対象ごとに「誰が・何を前提に・何を満たせば次へ進むか」を先に洗い、その結果として型が揃わないなら揃えない。

## 3. 登場人物を網羅する
判断の行為が資料に書かれているのに、その主体が役割の表にいない状態を作らない。役割を定義したら、対象別の関与（◎責任／○材料提供）まで作る。

## 4. 起点が違えば、別の資料として両方作る
同じ材料でも「成果物の起点」と「ゲートの起点」は使う場面が違う。

## 5. 一覧・フローを作ったら、示唆があるか点検する
一般論に終わっていないか、その対象に固有の事実が入っているかを確かめる。

## 6. 計画書・提案書は「目指す姿」から入る
冒頭で課題 → 目指す姿 → 阻んでいるもの → 進め方 → この取り組みの位置づけを示してから、手段（データモデル・製品など）に入る。
**Why:** 手段の話から始まる計画書は「ついていけない」と指摘された。
