# AI との作業の進め方

## 1. 着手の前に読む
作業の前に `rules/README.md` と関係するルールを本文まで読む。新しい資料・設計に入るときは、`rules/` を全件と `rules/project/` を読んでから構成を決める。
**Why:** 決めたことが多くのファイルに分かれていて、目先の1件だけでは方針を取りこぼす。
**How to apply:** 読んだうえで、今回の作業に効くルールを3〜5点、作業の最初にユーザーへ短く示す。

## 2. 文書は直接編集せず、スクリプトで作る
docs/ の Excel・pptx は、変更ごとに Python のスクリプトを `doc_tools/work/` に書いて作る。決まった形の文書（データ定義書など）は、値のファイル（JSON）を直して決まったスクリプトで作る。
**Why:** 手で直すと、何を変えたかが残らず、体裁が毎回ぶれる。スクリプトなら、やり直しと見直しができる。
**How to apply:** スクリプトの冒頭で「出力先が既にあれば止める」assert を入れる。失敗したように見えても、すぐ再実行せず、先に出力ができていないか確かめる。

## 3. 版を上げる。元の版は上書きしない
新しい版のファイル（`_v0.1` → `_v0.2`）を作る。確かめたら古い版を docs/ から消してコミットする（過去の版は Git の履歴に残る）。docs/ には各文書の最新版を1つだけ置く。
**Why:** 同じ文書が2つあると、どちらが正か分からなくなり、道具も止まる（`check_all.py` は定義書が2つあると NG にする）。

## 4. 確かめてから報告する
作ったものは、決まった確かめ方で確かめてから報告する。
- データ定義書：`python doc_tools/definition.py check <定義書>`
- アプリ：`python check_all.py --no-office`（生成・全画面・文言）
- pptx：`python doc_tools/render_pptx.py <pptx>` で PNG にして全ページを見る
- 全体：`python check_all.py`

**Why:** AI の出来は、正解と比べる手段があるかで決まる。確かめる手段があれば、合格するまで自分で直せる。
**How to apply:** NG が出たら直して流し直す。直せずに残ったものは、そのまま報告する（OK と言わない）。

## 5. 決めるのはユーザー
次のことは、作る前にユーザーに確かめる。
- 実現したいこと（To-Be像）
- データモデルの範囲・粒度（1行の単位）・正とする所
- 判定の閾値、色・信号（注意・要対応など）を付けること
- 資料の構成（会議の段階、載せる・載せないページ）
- ファイルの削除、外部への送信（メールは下書きまで。送らない）

**Why:** これらは業務の判断で、AI がもっともらしく決めると、後で全体を作り直すことになる。
**How to apply:** 選択肢と推奨とその理由を示して確かめる。決まったことは `rules/project/` に書く。

## 6. 返答は日本語で書く
作業が長く続いても、ユーザー向けの文は日本語にする。ツールの出力やコードが英語でも同じ。
**Why:** 長い作業の途中で英語に切り替わり、何度も指摘された。

## 7. ユーザーの指摘はルールにする
同じ指摘を2度受けないよう、指摘と理由を `rules/`（どのプロジェクトでも効くもの）か `rules/project/`（このプロジェクトだけのもの）に書く。
**Why:** AI は会話をまたいで覚えていない。ルールのファイルが記憶の代わり。
**How to apply:** 「何を言われたか（例）・なぜか・次からどうするか」を書き、`rules/README.md` の索引に1行足す。
