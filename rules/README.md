# 作業ルールの索引

どのプロジェクトでも使うルール。作業の前に、この索引から関係するファイルを本文まで読む。新しい資料・検討・設計に入るときは、全件を読んでから構成を決める（ルールが複数のファイルに分かれていて、目先の1件だけでは取りこぼすため）。

各ファイルは「ルール → **Why:**（理由）→ **How to apply:**（使い方）」の順で書く。理由があると、書かれていない場面でも判断できる。

## 進め方
- [AI との作業の進め方](working-with-ai.md) — 着手前に読む、直接編集せずスクリプトで作る、版を上げる、確かめてから報告する、決めるのはユーザー
- [データモデルの考え方](data-model.md) — 事象→課題→To-Be像→データモデル→ルールの順、To-Be像は判断・データ・自動化の形で、素の事実だけ入力・導出は計算、1行の単位と正とする所、テーブル単位→項目単位
- [業務画面の作り方](screen-design.md) — 画面は業務の単位、判断を求める画面には問い・診断・原因・推奨、閾値はマスタから

## 資料の書き方
- [説明資料の文章](business-doc-writing.md) — 1文・断定形、内輪の注記なし、あいまい語・比喩なし、体言止め、見出しは業務の名詞句、言い過ぎない
- [資料の構成](doc-structure.md) — 項目立てを全要素で揃える、対象の特性で構成を変える、登場人物を網羅、目指す姿から入る
- [会議の段階に合わせる](meeting-stage.md) — イメージ合わせ・論点整理・意思決定のどの段階かで載せるものを変える
- [pptx の体裁](pptx-format.md) — 色で意味づけしない、本文14pt、テンプレート踏襲、赤波線対策、PNG で確かめる、ページごとに図の形を変え注目点を1つ作る
- [アーキテクチャ図](architecture-slide.md) — 箱と矢印の図で機能とデータの配置を1枚に、表にしない
- [設計メモでは理由を残す](keep-the-why.md) — 説明資料と逆。メモでは理由・目的・使い方を削らない
