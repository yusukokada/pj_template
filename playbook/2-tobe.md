# 2. To-Be像

## 目的
課題が解けた状態を、判断とデータの言葉で決める。データモデルは「この To-Be像を実現するには、どのデータが要るか」で決まるため、To-Be像が無いとデータモデルの範囲が決まらない。

## 作るもの
検討メモに「領域別の To-Be像」の章を足す（版を上げる）。領域ごとに次を書く。
| 項目 | 内容 |
|---|---|
| To-Be像（全文・短縮版） | その状態を体言止めの1文で。短縮版は資料に載せる長さ |
| 実現する判断 | 誰が・いつ・何を決めるか |
| 他領域から受け取るデータ／他領域へ渡すデータ | 領域をまたいで使うデータ |
| 追加の作業 | 現場に新たに求める記録（既存の様式の変更か、初回だけの作業に抑える） |

## 進め方
1. ユーザーに「実現したいこと」を示してもらう（AI は聞き出し、候補を出す。決めるのはユーザー）
2. 自動化する判断を洗い出す。判断の材料は自動で算出し、見直し・中止・廃止の候補は自動で抽出し、人は抽出された候補について判断する形にする
3. 領域ごとに To-Be像を書く。課題の裏返し（「〜できない」を「〜できる」にしただけ）にせず、ほかの領域のデータを使うことで初めて得られる判断を軸にする
4. 段階1の目指す姿と突き合わせ、差があれば理由を書く
5. 各領域に新たに求める作業を明記する

## 確かめ方
- すべての課題が、どれかの To-Be像の判断で解ける
- 各 To-Be像に、実現する判断と使うデータが書いてある
- 体制・会議体の見直しだけで解く形になっていない（判断の基準をデータの側に持たせている）

## ユーザーに確かめること
- 実現したいこと
- To-Be像（全文・短縮版）
- 現場に求める追加の作業の範囲

## 次へ進む条件
To-Be像にユーザーが合意した。

## 依頼の例
〈〉は差し替える部分。

> 「私が実現したいことは〈実現したいこと〉。合意した課題と目指す姿を突き合わせて、領域ごとの To-Be像を『どの判断を、どのデータで、どう自動化するか』の形で書いて。課題の裏返しにはしないで。データモデルにはまだ進まないで」

伝えること：
- 実現したいこと（人が示す）
- 判断・データ・自動化の形で書くこと
- 次の段階に進ませないこと
