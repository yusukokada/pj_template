# 3. データモデル

## 目的
2 の To-Be像の判断に要るデータを、テーブルと項目に落とす。ルールは [rules/data-model.md](../rules/data-model.md)。

## 作るもの
`docs/【データ定義書】（テーマ）_v0.1.xlsx`。体裁は `doc_tools/definition.py` が決める（シート：00_凡例・01_テーブル一覧・02_領域・90_全項目・91_コード値案）。

## 進め方
1. 雛形の JSON を作る：`python doc_tools/definition.py new doc_tools/work/def.json`
2. **テーブル単位**：領域（areas）とテーブル（tables）を書く。各テーブルに 層・1行の単位・正とする所・管理するデータ・用途 を入れ、項目はキーだけにする
3. 定義書にする：`python doc_tools/definition.py build doc_tools/work/def.json "docs/【データ定義書】…_v0.1.xlsx"`
4. ユーザーにテーブル一覧を見せて確かめる（ここで合意してから項目に進む）
5. **項目単位**：項目・型・参照先・必須・取得・説明、区分の選択肢（codes）を書き、版を上げる
6. 2 の To-Be像の「実現する判断」と「受け取る・渡すデータ」がすべて、どこかの項目か導出のテーブルで出せるかを突き合わせる

既にある定義書を直すときは、`definition.py dump` で JSON にしてから直し、`build` で新しい版にする。ユーザーが Excel を直接直した場合も、次の版はその Excel を dump して作る（Excel が正）。

## 確かめ方
- `python doc_tools/definition.py check <定義書>` で誤り 0 件。気づきは1件ずつ、直すか理由を説明する
- To-Be像の判断と突き合わせ、データで出せない判断が残っていない
- 導出のテーブルの各項目に、何から計算するかが説明に書いてある

## ユーザーに確かめること
- テーブルの切り方と1行の単位、正とする所
- 扱わないデータ（範囲の外）
- 導入する製品の標準との対応を取るか

## 次へ進む条件
テーブル一覧と1行の単位にユーザーが合意し、check で誤りが 0 件。

## 依頼の例
〈〉は差し替える部分。

> 「合意した To-Be像から、データ定義書のテーブル一覧を作って。各テーブルに層・1行の単位・正とする所を書き、項目はキーだけでよい。definition.py check で誤り0件にしてから見せて」
>
> テーブル一覧に合意したら：「テーブル一覧は合意した。項目を詰めて版を上げて。To-Be像の判断が全部データで出せるかを突き合わせた結果も付けて」

伝えること：
- テーブル単位から始め、項目は後にすること
- 書いてほしい欄（層・1行の単位・正とする所）
- 確認方法（check で誤り0件）
